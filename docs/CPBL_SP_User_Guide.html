02 / SIMULATOR正式試算器怎麼用

  1. 設定投打與打序。選擇進攻球隊、守備球隊、打者、對方投手及下一棒；下一棒不能與本棒是同一人。
  2. 設定場上局面。選出局數，勾選一、二、三壘跑者。
  3. 設定本球位置。在進壘圖上點選，或調整左右 x／高度 z；單位為公尺，圖為從投手方向看本壘。
  4. 確認推論版本。可選 v0.6 逐球到得分研究版，或 v0.4 位置修正保留版。展開「本球資訊與球數」設定球速、投球前球數；選填量測若未知，保持空白。
  5. 設定擊球與結果。可調落點、仰角、擊球初速，再選一壘安打、出局、保送等打席結果。擊球資訊主要影響擊球出局率與研究歸因；目前不直接改寫選定結果的價值 V。
  6. 閱讀結果。畫面會隨輸入更新。先看「情境事件 SP · 進攻方」及其說明，再看 RE24、各種結果機率與分段歸因。
做比較時，一次只換一個條件。
例如固定打者、投手、結果與局面，只換下一棒，觀察事件後價值與 SP；或固定其餘條件，只換進壘位置，觀察機率與預期基準。這是模型情境試算，不代表改動條件的因果效果。

若使用 v0.6，先確認狀態列顯示研究模型已載入。載入失敗時畫面可能暫用保留版，請以狀態列顯示的實際版本記錄結果。

03 / READ THE RESULTSP 數字代表什麼

情境事件 SP＝本次結果的得分價值 − 模型預期得分價值本次結果價值＝平均直接得分＋打席後預期得分；預期基準＝各種可能結果的價值，依模型機率加權。

單位是分（runs）。正值表示本次結果比模型預期更有利於進攻；負值表示低於預期。它不是勝率。

v0.4 的既有示例：王順和對王維中、兩出局二壘有人，指定一壘安打，在對應預設下一棒與位置下，1.1026 − 0.3548＝+0.7478 分。切換版本或輸入後，結果可能不同；此例為情境推論，非實際打席重播。

畫面數字怎麼讀需要注意
情境事件 SP結果價值 V 減掉模型預期 E1。主要事件指標，進攻方正向。
事件 RE24直接得分＋事件後 RE−事件前 RE。事件價值對照基準，與 SP 的預期基準不同。
投手資訊貢獻E0−E1，壓低進攻期待為正。防守方方向，仍屬研究歸因。
打者擊球貢獻E2−E1，擊球價值高於位置期待為正。只對適用擊球事件拆分。
守備結果貢獻E2−V，結果比擊球期待更利於防守為正。包含未拆跑壘與結果殘差，未建立個人野手能力模型。
個人貢獻的方向與基準不同，不可直接相加當成事件 SP。球員選單的存在，也不代表該球員的個人守備能力已納入模型。

05 / LOCAL USE下載後如何在電腦使用

1. 取得完整專案

以有存取權的帳號開啟模型 repo，使用 Git clone，或在 GitHub 點 Code → Download ZIP 後解壓。終端機切到 repo 根目錄，再進入集中引擎：

cd models/integration/sp_engine

2. 先跑一個結果

建議 Python 3.12。以下凍結推論只使用 Python 標準函式庫，不需先安裝訓練套件或解壓原始資料：

python trace_model.py --mode legacy
python trace_model.py --mode v06
python trace_model.py --mode v06 --next 朱育賢

輸出 JSON 會顯示 event_SP、E0、E1、V_selected 及機率。比較兩次輸入時，先確認模式、選定結果與其他條件一致。

3. 開啟網站快照

python serve_handoff.py

在瀏覽器開啟 http://localhost:8000，結束時在終端機按 Ctrl+C。請使用本地伺服器，讓瀏覽器能讀取模型 ZIP 並驗證 SHA256。

本地快照是整理當下的版本，之後可能與正式網站不同。此使用說明頁屬網站 repo；舊快照裡不一定包含本頁。

06 / MODIFY & TRAIN要修改或重訓時怎麼做

以下指令都在 models/integration/sp_engine/ 執行。先確認要改的版本與比較基準，保留凍結權重。

v0.6：準備獨立環境與資料

python -m venv .venv-v06

Windows 啟用：.venv-v06\Scripts\activate；macOS／Linux 啟用：source .venv-v06/bin/activate。

python -m pip install -r requirements-v06.txt
python setup_data.py
python work/validate_pitch_runs.py --data data/CPBL_2026_predict_data/data --output results/local-v06

setup_data.py 先核對全部 17 段與整包雜湊，再解壓資料。新結果寫入 results/local-v06/，原 results/v06/ 保留作比較。

重建本地網站資產

python work/package_runtime.py --results results/local-v06
python serve_handoff.py

這會重建本地模型資產並更新本地載入雜湊；請記錄新資產路徑、測試與成績。這一步不會自動更新正式網站。凍結驗收測試仍以原 results/v06 為準；新權重需另做對應的 Python／JavaScript 一致性檢查。

舊版與 v0.5

舊打席／下一棒模型完整重訓還需要 repo 根目錄的歷年事件表，以及精確版本的已審核 --known-lineup 輸入；細節見 README_FIRST.md。v0.5 封存 joblib 使用的 sklearn 版本與 v0.6 不同，請依各版本說明建立環境。

07 / VERIFY怎麼確認有改對

要確認什麼方法通過代表什麼
凍結檔案完整python verify_manifest.py與整理時的 SHA256 相符；修改凍結資產後不應再期待原清單通過。
計算邊界與推論python -m unittest discover -s work -p 'test_*.py'凍結模型的球數轉移、匯出及交接驗收通過。
跨語言一致性node work/test_runtime.cjs凍結 Python／JavaScript 推論一致，不代表新模型準確度提升。
模型有沒有改善同測試期間比較 Log Loss、Brier 與校準；得分另比較 RMSE／MAE。標示樣本數、時間切分與驗證範圍，沒有結果就寫待驗證。
正式上線完成確認 Pages 部署成功，再開正式首頁與說明頁。能看到新版入口、頁面與實際推論狀態；提交成功不等於部署成功。

目前 v0.6 的時間切分開發測試涵蓋 2026/8/23–10/6，23,906 球；得分比較為 6,326 個可追蹤的 0-0 打席起點。逐球機率優於情境／歷史基準，但剩餘得分尚無足夠證據穩定優於 RE24。後段曾反覆用於開發，並非全新保留測試。

離線得分驗證使用聯盟後續 RE，未涵蓋網站完整下一棒擴充或個人責任正確性。完整成績與限制請讀模型 repo 的 results/v06/README.md、metrics.json。

08 / FAQ常見問題

為什麼 GitHub 的模型或資料連結打不開？

模型 repo 為私人儲存庫。請登入有權限的帳號；若仍顯示 404，請由擁有者確認存取權。正式試算器與本說明頁可公開開啟。

為什麼某位球員顯示「基準能力」？

球員名單與模型資料分開更新。球員列在名單中，不保證模型有足夠的個人資料；此時會使用對應的平均／先驗能力，請留意畫面提示。

v0.6 載入中或失敗，該怎麼辦？

檢查連線並重新整理，查看狀態列的實際版本。必要時切換 v0.4 保留版。記錄結果時要註明實際使用版本；本地使用請以 localhost 啟動。

選一個野手，數字就代表他的真實守備能力嗎？

目前沒有個人野手能力模型；守備欄是結果相對擊球期待的研究殘差，也含未獨立拆分的跑壘與誤差，不能當成已驗證的個人能力。

為什麼改了模型 repo，正式網站沒有變？

模型 repo 與網站 repo 分開。sp_engine/site/ 是快照；正式網站由 cpbl-sp-simulator 部署。更新模型後，還要核對並同步網站所需資產、等待部署，再實測正式頁。

要交接給隊友，先給哪三個入口？

先給本使用說明頁、模型 repo 根目錄 PROJECT_FILE_MAP.md，以及 models/integration/sp_engine/README.md。需要上台展示時，再使用該目錄 docs/ 的 14 頁簡報。
